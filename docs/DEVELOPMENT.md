# Development notes

Author and maintainer: **Efren C.D.**

## Layout

| Component | Responsibility |
| --- | --- |
| MainActivity | Native SRT controls, capture lifecycle and reconnect scheduling. |
| PhoneStabilization | Exclusive native EIS/OIS requests, asynchronous readiness retries and capture-result status. |
| RecoveryMonitor | Pure Java monotonic-time timeout/retry policy. |
| AdaptiveBitrate | Pure Java bounded adaptation using SRT/network feedback. |
| AudioInputPolicy | Route preference with USB-to-internal fallback. |
| AudioInputRouter | Android input enumeration, live routing and actual-device reporting. |
| SidebarPanel / PanelLinks | Persistent foreground receive-only panel, icon tabs, URL validation and about. |
| MicrophoneMeter / PcmLevel | Unmodified SRT PCM peak analysis and local dBFS overlay. |
| NinjaWhip | HTTP negotiation with VDO.Ninja for the native WebRTC publisher. |
| VdoLinks | Stream URLs and exact HTTPS origin validation. |
| LocalizedActivity / UiLanguage | Spanish for a primary Spanish locale, English otherwise. |

Policy tests in `tests/es/colegio/camara` run without Android. They cover retry deduplication/cancellation, timeouts, bitrate recovery/congestion bounds, USB fallback/replug selection and URL validation. They do not exercise hardware, codecs, Android routing decisions, NAT traversal or OBS reception.

## Localization

The main activity wraps their configuration using the primary system language, or an explicit Android 13+ per-app override: `es` selects Spanish, everything else selects English. Do not read only the incoming Activity locale order, which Android may already have reordered to prefer a supported secondary language. A normal locale configuration change recreates the activity, releasing capture using the existing foreground lifecycle; it does not silently resume publishing. English resources are complete defaults and Spanish resources have matching keys and formatting arguments. UI language selection has a pure Java test; the UI was checked in an API 36 emulator with English, Spanish variants and French with secondary Spanish. VDO.Ninja web content retains its own localization.

## Native stabilization

PhoneStabilization uses Camera2 characteristics and RootEncoder 2.8.1 public setCustomRequest/setCustomOnCaptureCompletedCallback APIs. It waits up to 3 s for the asynchronous camera request builder, requests only advertised controls and explicitly disables the other stabilization mode. Capture-result metadata confirms the actual mode; missing/contradictory metadata stays unconfirmed. A generation token and callback cancellation prevent requests to a released camera. The SRT-only selector defaults off, persists across sessions and is disabled during publishing.

## Audio bridge

RootEncoder 2.8.1 does not expose AudioRecord for this camera API. AudioInputRouter reads `Camera2Base.microphoneManager` and `MicrophoneManager.audioRecord` using a guarded reflection bridge, then public Android `setPreferredDevice` and `getRoutedDevice` APIs. It does not replace the recorder or use Android hidden APIs.

Review field names, obfuscation/keep rules and lifecycle behavior before upgrading the dependency or enabling shrinking. Preferred and actual routes can differ; do not present a device as confirmed before Android reports it.

## Director panel and microphone meter

SidebarPanel is shared by both activities. The configured HTTP(S) URL and audio preference are stored in a separate private preference file. No JavaScript bridge, capture permissions, location permissions, file/content access, cross-origin top-level navigation, popup window or TLS bypass is provided. HTTP is explicitly enabled for LAN text panels; HTTPS pages still disallow mixed content. This is a general embedded page, not a bundled chat or intercom server.

Changing tabs hides views without destroying the page. Activity pause and explicit close destroy the WebView to stop playback/connections. No global audio mode, speakerphone or communication-device setting is changed. WebViewCompat MUTE_AUDIO is feature-checked before muting and defaults off; unsupported engines expose an explicit Android-volume fallback. There is no per-WebView output routing API here, and device presence is not treated as proof of a playback route. Headphone removal never closes the page.

SRT setCustomAudioEffect observes PCM16 and returns the original array. The meter aggregates peak amplitude across channels and UI intervals, holds peaks for 1 s, clears on capture teardown and explicitly represents mute. Only the UI thread draws; generation checks discard old capture callbacks. This does not open an idle microphone.

The existing receive watchdog uses per-UID TrafficStats, not per-socket SRT ACKs: traffic generated by the web panel can mask this auxiliary silence heuristic. Transport error/disconnect handling and the connection-attempt timeout remain active. A dedicated SRT receive counter would be preferable to the UID heuristic in a future transport revision.

API 36 emulator checks for 0.14 include native ES/EN tabs, retained web page state, denied getUserMedia camera/mic requests, SRT H.264/AAC reception by a local FFmpeg listener with the panel open, and microphone mute state. These checks do not establish physical USB/headphone routing or production network stability.

## Native VDO.Ninja publisher

NinjaWhip negotiates an outgoing native WebRTC peer through the documented WHIP endpoint. OBS opens the VDO.Ninja receiver URL generated by VillaCam. The configurable sidebar WebView remains a receive-only director panel.

## Build and release

Use the Gradle wrapper, JDK 17 and SDK 35. D8/R8 is overridden because runtime dependencies contain metadata newer than the bundled compiler supports. The older lint analyzer can still emit Kotlin metadata diagnostics; inspect reports rather than treating task success as full dependency analysis.

Keep application ID `es.colegio.camara` for updates. Keep signing material outside Git. Debug keys differ across machines. Locally delivered APKs are test builds, not a long-term release signing arrangement.

The public repository is `efrencd/VillaCam`, licensed under Apache-2.0. Keep only source/assets/wrapper files in Git. Local APK deliveries, logs, SDK paths, build output and signing files are ignored. Publish test APKs as clearly labeled preview release assets, with accompanying license notices. Never publish signing keys.
